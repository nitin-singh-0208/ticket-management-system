# Data Model: Ticket RAG Assistant

Public JSON names are camelCase. Phase 1 ticket entities are unchanged; this document covers vector-store documents, domain events, and the ask API.

## Vector document (Spring AI `Document`)

Each chunk stored in PGVector `vector_store` represents searchable ticket text.

| Field | Storage | Rules |
|-------|---------|--------|
| id | `uuid` (PGVector table) | Generated by `uuid_generate_v4()`. |
| content | `text` | Header line, then the section text (or a paragraph fragment after split). The `search_document: ` prefix is applied only when calling the embedding model; it is not stored. |
| embedding | `vector(768)` | From Ollama `nomic-embed-text`. Dimension fixed at table creation. |
| metadata | `json` | See metadata table below. |

### Chunk metadata (every document)

| Key | Type | Source | Rules |
|-----|------|--------|--------|
| `ticketId` | string | `tickets.ticket_id` | Public id, e.g. `TKT-1001`. Used for delete-by-filter on re-ingest. |
| `status` | string | `tickets.status` | Current status at index time. |
| `priority` | string | `tickets.priority` | `LOW`, `MEDIUM`, or `HIGH`. |
| `assignee` | string | `tickets.assignee` | Free text. |
| `category` | string | `tickets.category` | e.g. `Payment`, `Shipment`, `Login`. |
| `sourceType` | string | derived | `description`, `comment`, or `resolution`. |

### Knowledge document → chunk mapping

One knowledge document per ticket section before chunking:

| sourceType | Source row | When omitted |
|------------|------------|--------------|
| `description` | `tickets.description` | never (required field) |
| `comment` | `comments.text` | one document per comment |
| `resolution` | `tickets.resolution_notes` | skipped when null or blank after trim |

`TicketDocumentMapper` splits each section paragraph-based: max ~800 tokens per chunk; ~100 token overlap only when a single section exceeds the limit.

Every chunk’s `content` starts with this header, then a newline, then the section text:

```text
Ticket {ticketId} | {title} | status {status} | priority {priority} | category {category} | section {sourceType}
{section text}
```

Example:

```text
Ticket TKT-1001 | Payment declined at checkout | status OPEN | priority HIGH | category Payment | section description
Card network returned a payment failure during checkout.
```

The same header is the first line of each LLM context block. `assignee` stays in metadata and is not part of the header.

### Re-ingestion invariant

For a given `ticketId`, **all** existing vector rows with that metadata value are deleted before new documents are added. No orphaned chunks.

## TicketChangedEvent

| Field | Type | Rules |
|-------|------|--------|
| ticketId | string | Public ticket id (`TKT-xxxx`). |

Published after successful commit from:

- `TicketService.createTicket`
- `TicketService.updateTicket`
- `TicketService.changeStatus`
- `CommentService.addComment`

Consumed by `TicketIndexer` (`@TransactionalEventListener(phase = AFTER_COMMIT)`, `@Async`). The listener method reloads the ticket and its comments inside `@Transactional(readOnly = true)`. `@EnableAsync` is on the application so the listener runs on the async executor. `TicketIndexer` and `VectorStoreBackfill` exist only when `app.rag.indexing.enabled` is `true` (`matchIfMissing = true`).

## Ask request

`POST /api/ai/ask`

| Field | Type | Rules |
|-------|------|--------|
| question | string | Required. Trimmed. Max 2000 characters. Blank → HTTP 400. |

## Ask response

| Field | Type | Rules |
|-------|------|--------|
| answer | string | Grounded answer text, or exactly `No relevant tickets found` when `grounded` is false. |
| sources | array | Empty when `grounded` is false. Otherwise one entry per cited ticket, taken from retrieved chunks. |
| grounded | boolean | `true` only when retrieval was non-empty and every ticket id cited in the answer was retrieved, and at least one retrieved id was cited. |

### Source entry

| Field | Type | Rules |
|-------|------|--------|
| ticketId | string | Public id from the winning retrieved chunk. |
| title | string | From that chunk’s header line. |
| status | string | From that chunk’s metadata (status at index time). |
| score | number | Highest similarity score among retrieved chunks for that `ticketId` (0–1, higher = more relevant). |
| snippet | string | Up to 300 characters of section text from that highest-scoring chunk (header excluded). |

### Sources and citation rules

1. Group retrieved chunks by `ticketId`. Keep the chunk with the highest score.
2. Parse ticket ids cited in the answer text (`TKT-` plus digits).
3. `sources` is that grouped set filtered to ids that appear in the answer.
4. If the answer cites no retrieved id, return `answer` = `No relevant tickets found`, `sources` = `[]`, `grounded` = `false`.
5. If the answer cites any id that was not in the retrieval set, return the same no-match body. Do not return the model text with the bad id removed.
6. Empty retrieval never calls the chat model and returns the same no-match body.

## Retrieval configuration (`app.rag`)

| Property | Type | Default | Rules |
|----------|------|---------|--------|
| top-k | integer | 5 | Passed to `SearchRequest.topK`. |
| similarity-threshold | number | 0.6 | Starting value, passed to `SearchRequest.similarityThreshold`. Calibrate from DEBUG retrieval scores; record the chosen value in `specs/evaluation-strategy.md`. |
| indexing.enabled | boolean | true | `false` in test `application.yml`. Gates `TicketIndexer` and `VectorStoreBackfill`. |
| chat-model | string | `llama3.1:8b` | Documented mirror; actual chat model set via `spring.ai.ollama.chat.options.model`. |
| embedding-model | string | `nomic-embed-text` | Documented mirror; actual embedding model via `spring.ai.ollama.embedding.options.model`. |

## Backfill

On application startup, if `vector_store` has zero rows, index every ticket (same path as re-ingest per ticket). If any chunks exist, skip backfill.
